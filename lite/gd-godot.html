Godot field guide

The mental model: scenes, nodes, signals, resources, autoloads, physics layers and exporting.

The mental model

  • Everything is a node. Nodes form a tree; a scene is a saved tree you can instance inside other scenes. A level is a scene that contains player, enemy and tile-map scenes.
  • Call down, signal up. A parent calls methods on children it owns. A child announces events with signals and has no idea who listens.
  • Resources (.tres) are data objects shared between scenes: stats, items, themes. Create custom ones with class_name and @export fields, edit in the inspector.
  • Autoloads (singletons) for truly global services: audio manager, save system, event bus. Keep them few and thin.
  • Groups tag nodes (“enemies”) so you can call or query them without references.

GDScript in five lines that matter

class_name Player extends CharacterBody2D
@export var speed := 220.0               # editable in the inspector
@onready var sprite := $Sprite2D         # resolved when the node enters the tree
signal died
func _physics_process(delta):
    velocity.x = Input.get_axis("left", "right") * speed
    move_and_slide()

Use static types (var hp: int) for speed and earlier errors. Use await for timers and animations. When GDScript becomes the bottleneck you have options: C# (typed, fast, .NET), or GDExtension to write hot paths in C++ (godot-cpp), which is also the door through which Zig and Rust bindings exist.

Physics setup checklist

  1. Name your collision layers (player, world, enemy, player_bullet, pickup, hurtbox).
  2. For every object decide layer (what I am) and mask (what I detect).
  3. Use Area2D for hitboxes and hurtboxes, CharacterBody2D for the player.
  4. Do movement in _physics_process.

Project structure that stays sane

res://
  scenes/     player/  enemies/  levels/  ui/
  scripts/    (only shared code; per-scene scripts live next to the scene)
  assets/     art/  audio/  fonts/
  data/       items/  enemies/  (resources and JSON)

Exporting

  • Install export templates (Editor → Manage Export Templates), then add a preset per platform.
  • Web export works well for jams and portfolios. It needs cross-origin isolation headers for threads and has size and audio quirks. Host on itch.io or a static host that sets the headers.
  • Test an exported build early. Many problems (paths, missing resources, performance) only appear in release builds.
For pixel art: Project Settings → Rendering → Textures → default filter Nearest; Display → Window → Stretch mode canvas_items with an integer scale mode; enable Snap 2D Transforms to Pixel.

Answer key

1. Quick check back ↑

B. Coin emits a signal (or an autoload event bus emits one), and the HUD or a game-state node connects to it

The Coin should not know the HUD exists. Signals (or an event bus) keep scenes reusable and testable alone.

2. Quick check back ↑

B. Bullet on a “player_bullet” layer with mask = enemy (+ world); enemies detect that layer; the player's mask does not include it

Layers and masks are filtered by the engine's broad phase, which is faster and cleaner than branching in scripts.

3. Check 1 back ↑

A. In a thin autoload singleton, kept few in number so global state stays manageable

Autoloads suit truly global services, but each one is shared mutable state, so they stay few and thin.

4. Check 2 back ↑

B. Do movement in _physics_process at its fixed rate, reserving _process for visuals and UI

Gameplay movement belongs in the fixed-rate callback for stable simulation; per-frame visuals belong in _process.
