LLMs: the mental model you need

Tokens, context, sampling, cost/latency, and where they fail.

  • Tokens, not characters. Cost and latency scale with input + output tokens. Output tokens are generated one at a time, so long outputs are slow.
  • Stateless. The model remembers nothing between calls. “Memory” is you re-sending context. The context window is a hard budget; quality also degrades with noisy, very long context.
  • Sampling. Temperature/top-p trade determinism for variety. Use low temperature for extraction/classification. Even at 0, treat output as non-deterministic across versions.
  • Probabilistic, not authoritative. Models produce plausible text. They hallucinate, especially on rare facts, exact numbers, and APIs that changed. Ground with retrieved sources and verify with code.
  • Structured output & tools. Constrain outputs with schemas, let the model call tools (functions) for facts and actions, and validate everything it returns like untrusted input.
  • Prompt caching. Stable prefixes (system prompt, docs) can be cached to cut cost and latency. Put the stable content first.

Engineering levers when quality is poor

In order of cost: clearer instructions and examples → better context/retrieval → structured output + validation → tools → smaller task decomposition → a stronger model → fine-tuning (rarely first).

Answer key

1. Quick check back ↑

B. Retrieve the actual policy text and instruct the model to answer only from it, citing the source (and say “I don’t know” otherwise)

Grounding with retrieval + a refusal path addresses the root cause (missing facts). Telling a model not to hallucinate does little by itself.

2. Quick check back ↑

B. Retrieve only relevant passages, and cache the stable prefix if the whole document is genuinely needed

Tokens drive cost and latency: send fewer of them (retrieval, summarisation) or make repeated ones cheap (prompt caching).

3. Check 1 back ↑

C. In context you re-send every call, bounded by the context window

LLMs are stateless. Memory is re-sent context, so noisy or overlong context degrades quality and raises cost.

4. Check 2 back ↑

A. Constrain the output with a schema, validate it like untrusted input, and use a low temperature

Structured output plus validation enforces the contract and low temperature favours determinism; fine-tuning is the last resort, not the first.
