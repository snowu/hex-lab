Terraform & infrastructure as code

State, plan/apply, modules, drift, safety. Implement plan diffing and dependency order.

Terraform (or the open-source fork OpenTofu) is declarative: you describe the desired infrastructure, it compares that with the recorded state and the real world, and produces a plan of creates, updates and destroys. It builds a dependency graph from references between resources and applies independent resources in parallel.

resource "aws_sqs_queue" "payments_dlq" { name = "payments-dlq" }

resource "aws_sqs_queue" "payments" {
  name = "payments"
  redrive_policy = jsonencode({
    deadLetterTargetArn = aws_sqs_queue.payments_dlq.arn   # implicit dependency
    maxReceiveCount     = 5
  })
}

Things seniors are asked

  • State: maps config to real resources and may contain secrets in plain text. Use a remote backend (e.g. S3, encrypted, versioned) with locking so two applies cannot race (DynamoDB table historically, S3 native lockfile in newer versions), restricted access, and never commit state.
  • Drift: reality differs from state (console clicks). plan reveals it; fix by reapplying, importing, or updating the config. Prevent with restricted console access and drift-detection CI.
  • Safe delivery: PR → fmt/validate/lint/security scan → plan posted for review → approved apply from CI with least-privilege role. Apply the saved plan file so what was reviewed is what runs.
  • Modules: reusable, versioned, small interfaces. Don’t over-abstract; prefer composition. Pin provider and module versions.
  • Environments: separate state per environment/account (directories or workspaces with care). Blast-radius control: split state by lifecycle and ownership, not one giant state.
  • count vs for_each: with count, removing a middle element shifts indexes and may destroy/recreate resources. for_each with stable keys avoids that.
  • Refactoring: moved blocks rename without recreating; import adopts existing resources; lifecycle { prevent_destroy = true } guards stateful resources; create_before_destroy for zero-downtime replacement.
  • Danger: a plan that shows -/+ destroy and then create replacement on a database. Read plans carefully; -target is an escape hatch, not a workflow.
  • Secrets: don’t put them in variables with defaults or in state if avoidable; reference Secrets Manager/SSM, mark outputs sensitive (which only hides display, not state).

Answer key

1. Compute a plan (create / update / replace / delete) back ↑

Hint: Python’s == on dicts and lists is already a deep, key-order-insensitive comparison. The interesting part is deciding replace vs update: compare only the immutable attributes, using .get and “in” so a missing key counts as different from None.

Reference solution:

def plan(desired, current, immutable=frozenset()):
    out = {'create': [], 'update': [], 'replace': [], 'delete': []}
    for name in sorted(desired):
        if name not in current:
            out['create'].append(name)
            continue
        want, have = desired[name], current[name]
        if want == have:
            continue
        forced = any((k in want) != (k in have) or want.get(k) != have.get(k) for k in immutable)
        out['replace' if forced else 'update'].append(name)
    out['delete'] = sorted(name for name in current if name not in desired)
    return out

Real Terraform also computes values that are only known after apply, plans destroys in reverse dependency order, and shows a diff per attribute. Reading the plan for “forces replacement” on stateful resources is a core safety habit.

2. Apply order from a dependency graph back ↑

Hint: Kahn’s algorithm: count unmet dependencies per node, keep the ready ones in a heap (heapq) so you always take the alphabetically first, and decrement the dependants of each node you place. If you cannot place everything, there is a cycle.

Reference solution:

import heapq

def apply_order(graph):
    remaining, dependants = {}, {name: [] for name in graph}
    for name, deps in graph.items():
        for dep in deps:
            if dep not in graph:
                raise ValueError('unknown dependency: ' + dep)
            dependants[dep].append(name)
        remaining[name] = len(deps)
    ready = [name for name, n in remaining.items() if n == 0]
    heapq.heapify(ready)
    order = []
    while ready:
        name = heapq.heappop(ready)
        order.append(name)
        for nxt in dependants[name]:
            remaining[nxt] -= 1
            if remaining[nxt] == 0:
                heapq.heappush(ready, nxt)
    if len(order) != len(graph):
        raise ValueError('cycle')
    return order

The standard library has graphlib.TopologicalSorter (it raises graphlib.CycleError), but it does not guarantee a deterministic order among ready nodes. Terraform walks the same kind of DAG but runs independent nodes in parallel and applies destroys in reverse order.
