Perception and steering

What an agent knows (sight, sound, memory) and how it moves (seek, arrive, avoid, flock): the other half of believable AI.

Do not let the AI cheat by default

The easiest AI reads the player's position straight from the game state: it always knows where you are. That feels unfair and robotic. Perception is the layer that decides what an agent is allowed to know, and most "smart" behaviour is really good perception plus memory.

Sight

Three checks, cheapest first:

  1. Distance: closer than the sight range? (compare squared distances).
  2. Field of view: dot(facing, direction_to_target) > cos(half_fov) (no trigonometry in the loop).
  3. Line of sight: a raycast to the target that must not hit a wall (physics queries lesson). Stagger these across frames.

Refinements: visibility depends on light and stance (crouching or standing in shadow shortens range), peripheral vision (a narrow high-acuity cone and a wider low-acuity one), and a reaction delay before the AI acts on what it saw: awareness grows while you are visible and decays when you are not.

Hearing and other senses

Model sound as events, not audio: when the player runs, fires or breaks a bottle, post a noise event with a position and a loudness (radius). Agents within that radius, with walls attenuating it, are alerted to the noise position (not to the player). The same event system carries damage, allies calling for help and smells.

Memory and alert levels

  • Keep a last known position and a timestamp for each threat. When sight is lost, the agent goes to that point, searches, then gives up: this single behaviour makes AI feel intelligent.
  • A small number of alert states (unaware, suspicious, searching, combat) with clear telegraphs (a "?" and a "!", a change of colour or animation, a spoken line) lets the player read the AI and plan around it. Stealth games live on this.
  • Share information deliberately: an agent that spots you alerts nearby allies (with a delay and a range), not the whole level instantly.

Steering behaviours

Decision-making says where to go; steering says how to move so it looks natural. Craig Reynolds' steering behaviours return a desired acceleration for each frame:

  • Seek: accelerate toward the target. Flee: the opposite.
  • Arrive: seek, but slow down inside a radius around the target so the agent stops instead of overshooting and orbiting.
  • Pursue / evade: seek or flee the target's predicted position (position + velocity × time to reach).
  • Wander: steer toward a point on a small circle in front, nudged randomly each frame: aimless but smooth.
  • Obstacle avoidance: cast short feelers ahead and add a sideways push away from what they hit.
  • Separation, alignment, cohesion: avoid crowding neighbours, match their heading, move toward their centre. Together they produce flocking (boids), try the simulation.
  • Path following: seek the next waypoint on a path, switching when close.

Each behaviour first computes a desired velocity (toward the target at full speed, or scaled down when arriving). The steering acceleration is the difference between that and the current velocity, divided by a short time to target (0.1 to 0.25 s: how quickly the agent reacts; too large and it lags and overshoots, as the sample below shows).

Combine behaviours by a weighted sum or by priority (obstacle avoidance overrides everything), then clamp the total acceleration and speed (the drill from the vectors lesson). Weighted sums need tuning; priority systems are more predictable.

const std = @import("std");

const V = struct { x: f32, y: f32 };

fn len(v: V) f32 {
    return @sqrt(v.x * v.x + v.y * v.y);
}

fn limit(v: V, max: f32) V {
    const l = len(v);
    if (l <= max or l == 0) return v;
    return .{ .x = v.x / l * max, .y = v.y / l * max };
}

/// How quickly the agent tries to reach its desired velocity (seconds). Small = snappy, large = sluggish and overshoots.
const TIME_TO_TARGET: f32 = 0.1;

/// Desired velocity toward the target at full speed; the steering acceleration closes the gap to it over TIME_TO_TARGET.
fn seek(pos: V, vel: V, target: V, max_speed: f32) V {
    const dx = target.x - pos.x;
    const dy = target.y - pos.y;
    const d = @sqrt(dx * dx + dy * dy);
    if (d == 0) return .{ .x = -vel.x / TIME_TO_TARGET, .y = -vel.y / TIME_TO_TARGET };
    return .{ .x = (dx / d * max_speed - vel.x) / TIME_TO_TARGET, .y = (dy / d * max_speed - vel.y) / TIME_TO_TARGET };
}

/// Like seek, but the desired speed shrinks to zero inside slow_radius, so the agent stops at the target.
fn arrive(pos: V, vel: V, target: V, max_speed: f32, slow_radius: f32) V {
    const dx = target.x - pos.x;
    const dy = target.y - pos.y;
    const d = @sqrt(dx * dx + dy * dy);
    if (d == 0) return .{ .x = -vel.x / TIME_TO_TARGET, .y = -vel.y / TIME_TO_TARGET };
    const speed = if (d < slow_radius) max_speed * d / slow_radius else max_speed;
    return .{ .x = (dx / d * speed - vel.x) / TIME_TO_TARGET, .y = (dy / d * speed - vel.y) / TIME_TO_TARGET };
}

fn simulate(use_arrive: bool) f32 {
    var pos = V{ .x = 0, .y = 0 };
    var vel = V{ .x = 0, .y = 0 };
    const target = V{ .x = 100, .y = 0 };
    const dt: f32 = 1.0 / 60.0;
    var farthest: f32 = 0;
    for (0..60 * 20) |_| {
        const steer = limit(if (use_arrive) arrive(pos, vel, target, 80, 40) else seek(pos, vel, target, 80), 600);
        vel = limit(.{ .x = vel.x + steer.x * dt, .y = vel.y + steer.y * dt }, 80);
        pos.x += vel.x * dt;
        pos.y += vel.y * dt;
        farthest = @max(farthest, pos.x);
    }
    return farthest;
}

test "arrive stops at the target, plain seek overshoots and circles back" {
    const arriving = simulate(true);
    const seeking = simulate(false);
    try std.testing.expect(arriving < 100.5); // never overshoots
    try std.testing.expect(seeking > arriving + 3.0); // seek sails past
}

Crowds and avoidance

For many agents add local avoidance that predicts collisions with neighbours: velocity obstacles (RVO, ORCA) choose a velocity that avoids all predicted collisions within a short horizon. Most engines ship it (Godot's NavigationAgent avoidance, Unity's NavMeshAgent). Use flow fields for large groups heading to one goal (pathfinding lesson).

Debugging movement

Draw it: the desired velocity, the steering force, the target, the feelers, perception cones, last-known positions. Most steering bugs (orbiting a target, jitter at the destination, getting stuck on corners) are obvious once visible.

Simulation: Flocking from three simple rules

Each boid only reacts to neighbours inside its sight radius. Move the pointer over the canvas to attract them.

Try this in the full app:

  • Set separation to 0: the flock collapses into overlapping blobs.
  • Set alignment to 0: boids still cluster but move in all directions.
  • Set cohesion to 0: they stay aligned but drift apart.
  • Shrink the sight radius: separate small flocks form instead of one large group.
  • Move the pointer: the attraction is just one more weighted steering force added to the sum.

Answer key

1. Quick check back ↑

B. Store the last known position and make the guard go there and search for a few seconds before giving up

Memory plus a search behaviour reads as intelligence for almost no code.

2. Quick check back ↑

B. Arrive: reduce the desired speed inside a radius around the target

Arrive matches speed to distance so the agent decelerates and stops.

3. Quick check back ↑

B. As noise events with a position and loudness posted to nearby agents, which then react to the noise position

Events are cheap, controllable and testable. The AI reacts to where the noise happened, not to the player directly.

4. Check 1 back ↑

C. Sight checks should run cheapest first (distance, then field of view, then the raycast) and be staggered across frames

Ordering cheapest-first plus staggering keeps perception cheap; the raycast is the last resort, not the first.

5. Check 2 back ↑

A. Pursue the predicted position (position plus velocity times time to reach) instead of the current one

Pursuit leads the target while seek chases history; prediction is what hits movers.
