Tilesets, sprite sheets and the art pipeline

Tiles that connect, indexed colour and palette swaps, scaling rules, and keeping art in version control.

Tilesets

  • Pick a tile size (16×16 or 32×32 are the usual) and a layout grid. All tiles in a game share it.
  • Tiles must tile seamlessly: opposite edges match. Preview them in a 3×3 repeat while drawing.
  • Avoid a distinctive feature (a bright pebble) that makes repetition obvious. Make 2 to 4 variants of floor tiles and place them randomly.
  • Autotiling: instead of drawing every combination by hand, a tile is chosen by which of its neighbours are solid. With four neighbours (N, E, S, W) that is a 4-bit number, so 16 tiles. Including diagonals gives the 47-tile “blob” set. Godot 4 does the matching with terrain sets; you draw the tiles. The first drill below computes the bitmask.
  • Pad or extrude tiles inside an atlas by 1 pixel if you see seams between tiles when the camera moves (sub-pixel sampling pulls colours from the neighbouring tile).

Indexed colour and palette swaps

If the art uses a fixed palette, store it as indexed (each pixel is a palette index). Changing the palette changes all the art: enemy recolours, day and night, accessibility variants. Converting an arbitrary image to a palette is a nearest-colour search, the second drill. For smooth results add dithering; for pixel art you draw by hand you rarely need it.

Scaling and import

  • Render at the base resolution, scale up by an integer (third drill), centre with black bars if the window does not fit.
  • Godot: default texture filter Nearest; stretch mode canvas_items with integer scaling; snap 2D transforms to pixel; set import options to no mipmaps for pixel art.
  • Keep a single source of truth for sizes: tile size, base resolution and pixel scale in one constants file, not scattered.

Pipeline and version control

  • Keep source files (.aseprite, .pixelorama, or a layered format) in the repo next to the exported PNGs, or you lose layers and palettes forever.
  • PNG files are binary, so Git cannot merge them. Treat each sprite as a file with a single editor at a time, and use small, named commits (“slime: add hurt frame”).
  • GitHub shows image diffs in pull requests (2-up, swipe, onion skin), so art changes can be reviewed visually. Pair that with a naming convention and the artist can open PRs for art without touching code.
  • Automate export: a script that turns source files into the sheets and JSON the game loads, so nobody exports by hand.
  • Document the palette and sizes in the repo's README so any new artist can match the style.
The last lesson below sketches a reusable pixel editor that lives inside a game repo, finds the sprites, lets you edit them, and (optionally) proposes the change as a pull request.

Drill: Autotile bitmask

Tile maps pick the right edge or corner sprite from which neighbours are solid. Return a 4-bit number: N = 1, E = 2, S = 4, W = 8, each bit set when that neighbour is '#'. Cells outside the map count as solid, so the map border joins up. The result selects one of 16 tiles.

Starter (Zig):

const std = @import("std");

pub fn bitmask(grid: []const []const u8, row: usize, col: usize) u8 {
    _ = grid;
    _ = row;
    _ = col;
    return 0;
}

Drill: Snap an image to a palette

Implement nearest_index(rgb, palette): the index of the palette colour closest to rgb by squared Euclidean distance in RGB. The first one wins a tie. Then quantize(pixels, palette, out) maps a list of pixels to a list of palette indices (this is how a PNG becomes an indexed image).

Starter (Zig):

const std = @import("std");

pub const Rgb = [3]u8;

pub fn nearestIndex(c: Rgb, palette: []const Rgb) usize {
    _ = c;
    _ = palette;
    return 0;
}

/// out[i] = palette index for pixels[i]. out.len == pixels.len.
pub fn quantize(pixels: []const Rgb, palette: []const Rgb, out: []usize) void {
    _ = pixels;
    _ = palette;
    for (out) |*o| o.* = 0;
}

Drill: Pixel-perfect integer scaling

A pixel-art game renders at a low base resolution (say 320x180) and is scaled to the window. Non-integer scaling makes some pixels wider than others. Return the largest integer scale that fits (at least 1) and the offsets that centre the picture, using floor division (so a negative odd offset rounds down, towards minus infinity).

Starter (Zig):

const std = @import("std");

pub const Fit = struct { scale: i32, off_x: i32, off_y: i32 };

pub fn integerScale(win_w: i32, win_h: i32, base_w: i32, base_h: i32) Fit {
    _ = win_w;
    _ = win_h;
    _ = base_w;
    _ = base_h;
    return .{ .scale = 0, .off_x = 0, .off_y = 0 };
}

Answer key

1. Autotile bitmask back ↑

Hint: A helper solid(row, col) that returns true when the coordinates are outside the map or the character is #. Use signed integers for the neighbour coordinates: row - 1 on an unsigned 0 wraps around.

This is the 16-tile (4-bit) scheme. Adding the diagonals gives the 47-tile "blob" set, which needs corner checks so inner corners look right. Godot 4 terrain tiles do the matching for you, but you still have to draw the tiles. Draw the 16 first, then expand. (The unsigned wrap-around in the hint is a real bug source in C++ and Zig; Zig catches it in Debug builds with a panic.)

2. Snap an image to a palette back ↑

Hint: Squared distance in a wider type (i32): 255 * 255 * 3 does not fit in u8 arithmetic. Keep the best distance so far and only replace it when the new one is strictly smaller, which gives you the tie rule.

RGB distance is crude: human vision weighs green more and is not linear, so tools use perceptual spaces such as Oklab. Plain nearest-colour also bands; add dithering (see the dither simulation) to keep gradients. Working with an indexed palette is also what gives you palette swaps (enemy recolours) for free, and what Aseprite and most retro hardware used.

3. Pixel-perfect integer scaling back ↑

Hint: scale = max(1, min(win_w / base_w, win_h / base_h)). offset = floor((win - base * scale) / 2). Zig has @divFloor. C++ integer division truncates toward zero, so a negative odd numerator rounds the wrong way: write a small floor-division helper.

In Godot: Project Settings > Display > Window > Stretch: mode canvas_items (or viewport), aspect keep, scale mode integer. Set the default texture filter to Nearest and snap 2D transforms to pixel so sprites do not shimmer. Camera smoothing and sub-pixel movement are the usual cause of "swimming" pixels.

4. Quick check back ↑

B. Add 1-pixel extrusion/padding in the atlas and snap the camera to whole pixels

Sub-pixel positions sample the edge of the neighbouring atlas tile. Pad or extrude the tile edges and keep positions on whole pixels.

5. Quick check back ↑

B. The source keeps layers, palettes and animation data, so art can be edited later and exports regenerated

A flattened PNG has lost the information you need to change it safely.

6. Quick check back ↑

B. 10

E (2) + W (8) = 10. A vertical corridor (N and S) is 1 + 4 = 5.

7. Check 1 back ↑

A. Draw 2 to 4 plain variants and place them randomly so the repetition breaks up

A distinctive feature betrays the grid; variants plus random placement hide the repeat.

8. Check 2 back ↑

C. Store art as indexed colour against a fixed palette so swapping the palette recolours everything

Indexed pixels are palette references, so one art set yields many recolours from palette swaps.
