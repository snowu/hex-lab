Compute, data, messaging, networking, security and how to choose.

You are not expected to know every service. You are expected to pick appropriately, explain the trade-off, and design for failure.

Design for failure

  • Region → AZ: spread across ≥ 2-3 AZs. Multi-region only when RTO/RPO or regulation demands it (cost and complexity jump: data replication, failover, testing).
  • RTO/RPO: how long can we be down, how much data can we lose? Backup & restore → pilot light → warm standby → active/active, rising in cost.
  • Shared responsibility: AWS secures the cloud; you secure what you put in it (IAM, data, config).
  • Well-Architected pillars: operational excellence, security, reliability, performance, cost, sustainability.

Security fundamentals

  • IAM: least privilege, roles over long-lived keys, no wildcards on resources you can name, separate accounts per environment (AWS Organizations + SCPs). Evaluation logic: explicit Deny wins, otherwise an Allow is needed, otherwise implicit deny.
  • Private subnets for data/compute, VPC endpoints to reach AWS services without the internet, security groups as the main firewall.
  • Encrypt at rest (KMS) and in transit; CloudTrail + GuardDuty + Config for audit and detection. Particularly relevant in regulated finance.

Challenge (Python): Evaluate IAM-style policies

Implement evaluate(statements, action, resource) returning 'ALLOW' or 'DENY'. Each statement is a dict {'effect': 'Allow' | 'Deny', 'actions': [...], 'resources': [...]}. Patterns may contain * (matches any characters, including none; every other character is literal). Rules: if any matching Deny exists → DENY; else if any matching Allow exists → ALLOW; else DENY (implicit). A statement matches only if both an action pattern and a resource pattern match. Actions compare case-insensitively; resources are case-sensitive.

answer 4 ↓

Prompt: “Design deployments across two AZs with zero-downtime releases”

  • ALB across 2-3 AZs → ECS/Fargate or EKS services with ≥ 2 tasks per AZ; health checks with sensible grace periods.
  • Rolling or blue/green (CodeDeploy / weighted target groups) with automatic rollback on alarm; canary a small % first.
  • DB migrations backward compatible (expand → migrate → contract) so old and new code can run together.
  • Aurora/RDS Multi-AZ; Secrets Manager; autoscaling on a leading metric (queue depth/requests per target).
  • Observability tied to the release: dashboards and SLO alarms that gate the rollout.

Answer key

1. Evaluate IAM-style policies back ↑

Hint: Turn a pattern into a regex: split on "*", re.escape each piece, join with ".*", and use re.fullmatch (with re.IGNORECASE for actions). fnmatch is tempting but treats [] and ? as special.

Reference solution:

import re

def glob(pattern, ignore_case=False):
    regex = '.*'.join(re.escape(part) for part in pattern.split('*'))
    return re.compile(regex, re.IGNORECASE if ignore_case else 0)

def evaluate(statements, action, resource):
    def matches(s):
        return (any(glob(a, True).fullmatch(action) for a in s['actions'])
                and any(glob(r).fullmatch(resource) for r in s['resources']))

    hits = [s for s in statements if matches(s)]
    if any(s['effect'] == 'Deny' for s in hits):
        return 'DENY'
    return 'ALLOW' if any(s['effect'] == 'Allow' for s in hits) else 'DENY'

Real IAM also has principals, conditions, permission boundaries, SCPs and session policies. All layers must allow, and an explicit deny at any layer wins.

2. Quick check back ↑

B. SNS topic (or EventBridge) fanning out to one SQS queue per service, each with a DLQ

A single queue would split messages among consumers (competing consumers). Fan-out to a queue per subscriber gives each its own copy, retries and DLQ. Kinesis/MSK is the alternative if you need ordered replay.

3. Quick check back ↑

B. No: Multi-AZ gives failover availability (standby is not readable in the classic setup); scale reads with read replicas or caching

Availability vs read scaling are different mechanisms. (Aurora and newer RDS Multi-AZ cluster options have readable standbys, so be precise about which product and mode.) Multi-AZ also is not a backup.

4. Quick check back ↑

B. Set a maximum concurrency on the event source mapping / function (reserved concurrency) to cap parallel calls, plus retries with backoff and a DLQ

Queues + concurrency caps turn a spike into a controlled drain. Pair with a per-dependency rate limiter and circuit breaker.

5. Check 1 back ↑

C. No: an explicit Deny wins, and without any Allow the default is an implicit deny

IAM evaluation logic: explicit Deny wins, otherwise an Allow is required, otherwise access is implicitly denied.

6. Check 2 back ↑

A. Match cost to the RTO/RPO: a single region across 2-3 AZs with backups is enough, since multi-region jumps in cost and failover complexity

Choose backup-and-restore through active/active by RTO/RPO. Multi-region is for strict recovery or regulatory needs, not a default.
