Shaders, effects and 2D lighting

What a shader is, the handful of tricks behind most 2D effects, and how to light a flat world.

What a shader is

A shader is a tiny program that runs on the GPU, in parallel, for every vertex or every pixel. It cannot see the game; it only receives inputs and returns a colour. That restriction is why it is fast: thousands of copies run at once with no shared state.

  • Vertex shader: runs per vertex; positions things (a wobbling flag, a swaying tree).
  • Fragment (pixel) shader: runs per covered pixel; decides its colour. Most 2D effects live here.
  • Uniforms: values you set from the game for the whole draw (time, a colour, a threshold).
  • Varyings / UV: values interpolated per pixel; UV says which point of the texture this pixel is, from (0,0) to (1,1).
  • Textures: images the shader can sample at any UV.

Mental model: colour = f(uv, texture, uniforms, time), evaluated independently for each pixel. Anything that needs neighbours (blur) must sample the texture at several offsets; anything that needs history needs another render target.

Your first shader (Godot 4 shading language)

shader_type canvas_item;

uniform vec4 flash_color : source_color = vec4(1.0);
uniform float flash_amount : hint_range(0.0, 1.0) = 0.0;

void fragment() {
    vec4 tex = texture(TEXTURE, UV);
    COLOR = vec4(mix(tex.rgb, flash_color.rgb, flash_amount), tex.a);   // hit flash: blend toward white
}

Set flash_amount to 1 for a frame or two when the enemy is hit and tween it back to 0: that is the white flash from the juice lesson, with no extra art.

The classic 2D effects

  • Palette swap. Store the sprite in greyscale or index colours and look the colour up in a small palette texture: texture(palette, vec2(grey, row)). One sprite, many enemy variants, and day/night palettes for free.
  • Outline. Sample the alpha of the four neighbours; if this pixel is transparent but a neighbour is opaque, output the outline colour. (Mind the texture edge: pad the sprite by one pixel.)
  • Dissolve. Compare a noise texture to a threshold uniform; discard (or fade) pixels below it, and paint a bright rim just above. Animate the threshold for death and teleport effects.
  • Scrolling and distortion. Offset the UV by time (water, conveyor, heat haze) or by a noise texture (warp).
  • Scanlines and CRT. Darken every n-th screen row and add curvature or chromatic offset. Subtle, or it hurts readability.
  • Colour grading. A final full-screen pass: contrast, saturation, tint (damage vignette, underwater tint), usually via a lookup texture.
// outline: if I am empty but a neighbour is not, I am part of the outline
void fragment() {
    vec2 px = TEXTURE_PIXEL_SIZE;
    float a = texture(TEXTURE, UV).a;
    float n = texture(TEXTURE, UV + vec2(px.x, 0.0)).a + texture(TEXTURE, UV - vec2(px.x, 0.0)).a
            + texture(TEXTURE, UV + vec2(0.0, px.y)).a + texture(TEXTURE, UV - vec2(0.0, px.y)).a;
    COLOR = a > 0.5 ? texture(TEXTURE, UV) : (n > 0.5 ? vec4(0.0, 0.0, 0.0, 1.0) : vec4(0.0));
}

2D lighting

A flat world can still be lit. The pieces, from cheap to rich:

  1. Ambient tint. Multiply the whole scene by a colour (night = dark blue). One line.
  2. Light sprites. Draw soft round textures with additive blending into a separate "light buffer", then multiply the scene by that buffer. Torches, lamps, the player's lantern. Cheap and fully controllable.
  3. Shadows. Occluder shapes block light; engines build a shadow mask per light (Godot's PointLight2D + LightOccluder2D). The cost grows with lights × occluders.
  4. Normal maps. A second texture per sprite whose colours encode the surface direction, so a flat sprite reacts to the angle of the light and looks bumpy. Authoring cost is high; for pixel art many teams hand-paint a few and use a subtle effect.
  5. Emissive. Mark pixels that glow regardless of lighting (the "emissive pixels" some pipelines mark in the alpha channel), so lava and eyes stay bright in the dark.

Post-processing

Render the scene to a texture, then draw that texture to the screen through a shader. Bloom (blur the bright parts and add them back), screen shake of the whole view, pixelation, colour blindness simulation and fades are all post-effects. Each full-screen pass costs fill rate, so budget them on mobile.

Practical advice

  • Output values as colours to debug: COLOR = vec4(UV, 0.0, 1.0) shows the UV; COLOR = vec4(vec3(my_value), 1.0) shows any number as grey.
  • Avoid branching on uniforms per pixel when you can use mix or step; avoid dependent texture reads in loops.
  • Keep a shader's parameters per material, not per sprite, or batching breaks (graphics pipeline lesson).
  • Mobile precision: some GPUs use half-precision floats in fragment shaders; large UV offsets and time values can jitter. Wrap time with mod.
  • Pixel art: sample with nearest filtering and keep effects on whole pixels, or the effect shimmers.

Answer key

1. Quick check back ↑

B. Palette-swap shader: one greyscale/indexed sprite and a small palette texture lookup per variant

A palette lookup replaces individual colours exactly, keeps shading, and a new variant is just a new row in a small texture.

2. Quick check back ↑

B. Each pixel runs independently with no shared mutable state; you need a second render target holding the previous frame

The model is a pure function of inputs. History must be fed back in as a texture (ping-pong render targets).

3. Quick check back ↑

B. Additive soft light sprites drawn into a light buffer that the scene is multiplied by

It is just textures and blend modes: cheap, art-directable, and works on any hardware. Add occluders for shadows when needed.

4. Check 1 back ↑

B. If this pixel is transparent but one of its four alpha neighbours is opaque, output the outline colour; pad the sprite texture by one pixel so the rim has room

Outlines detect the alpha edge by sampling neighbours. Without padding the rim is clipped at the texture border.

5. Check 2 back ↑

A. Keep shader parameters per material rather than per sprite, or batching breaks: unique state per sprite forces a new call

Batching merges sprites sharing texture, material and blend mode. Per-sprite state splits every batch.
