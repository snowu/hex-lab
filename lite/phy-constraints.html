Constraints, ropes and cloth

Position-based dynamics: keep points at distance by relaxing constraints, the trick behind ropes, chains and cloth.

What a constraint is

A constraint is a rule the simulation must keep true: "these two points stay 10 units apart" (a rope segment), "this point stays here" (a pin), "this angle stays between 10° and 90°" (an elbow), "this body stays on this line" (a slider). Hinges, ropes, chains, ragdolls, vehicles and cloth are collections of constraints.

Position-based dynamics with Verlet

Instead of computing constraint forces (hard and stiff), do this each step:

  1. Integrate every point freely (Verlet, which stores the previous position instead of a velocity: velocity = position - previous).
  2. Relax the constraints: for each distance constraint between points A and B, measure the current distance, and move both points along the line between them by half of the error each (or all of it for the free one when the other is pinned).
  3. Repeat step 2 several times (the iterations): fixing one constraint disturbs its neighbours, and a few passes converge towards a state that satisfies all of them.

Because the velocity is derived from positions, correcting a position automatically corrects the motion. It is unconditionally stable (it cannot explode), simple to write and cheap, which is why it is everywhere in games (rope, hair, cloth, soft bodies, grappling hooks). The cost: the "stiffness" depends on the iteration count and the time step, so it is not physically exact, and long chains look stretchy unless you add iterations.

const std = @import("std");

const N = 8;
const REST: f32 = 10;

/// A rope of N points hanging from a pin at the origin. y grows downward.
const Rope = struct {
    x: [N]f32 = undefined,
    y: [N]f32 = undefined,
    px: [N]f32 = undefined, // previous positions: velocity is x - px
    py: [N]f32 = undefined,

    fn init() Rope {
        var r = Rope{};
        for (0..N) |i| {
            r.x[i] = @as(f32, @floatFromInt(i)) * REST; // starts stretched out horizontally
            r.y[i] = 0;
            r.px[i] = r.x[i];
            r.py[i] = r.y[i];
        }
        return r;
    }

    fn step(self: *Rope, dt: f32, iterations: usize) void {
        // 1. Verlet integration with gravity (point 0 is pinned)
        for (1..N) |i| {
            const vx = (self.x[i] - self.px[i]) * 0.99; // a little damping
            const vy = (self.y[i] - self.py[i]) * 0.99;
            self.px[i] = self.x[i];
            self.py[i] = self.y[i];
            self.x[i] += vx;
            self.y[i] += vy + 400.0 * dt * dt;
        }
        // 2. relax the distance constraints several times
        for (0..iterations) |_| {
            for (0..N - 1) |i| {
                const dx = self.x[i + 1] - self.x[i];
                const dy = self.y[i + 1] - self.y[i];
                const dist = @sqrt(dx * dx + dy * dy);
                if (dist == 0) continue;
                const diff = (dist - REST) / dist;
                if (i == 0) { // the pinned point does not move: the other one takes the whole correction
                    self.x[1] -= dx * diff;
                    self.y[1] -= dy * diff;
                } else {
                    self.x[i] += dx * 0.5 * diff;
                    self.y[i] += dy * 0.5 * diff;
                    self.x[i + 1] -= dx * 0.5 * diff;
                    self.y[i + 1] -= dy * 0.5 * diff;
                }
            }
        }
    }
};

test "the rope hangs under gravity, stays pinned, and keeps its segment lengths" {
    var r = Rope.init();
    for (0..600) |_| r.step(1.0 / 60.0, 30);
    try std.testing.expectEqual(@as(f32, 0), r.x[0]);
    try std.testing.expectEqual(@as(f32, 0), r.y[0]);
    // it has swung down below the pin
    try std.testing.expect(r.y[N - 1] > 40);
    // every segment is close to its rest length
    for (0..N - 1) |i| {
        const dx = r.x[i + 1] - r.x[i];
        const dy = r.y[i + 1] - r.y[i];
        const len = @sqrt(dx * dx + dy * dy);
        try std.testing.expect(@abs(len - REST) < 0.5);
    }
}

Other constraints

  • Pin / anchor: set the point's position each step (the first point above).
  • Max-length (rope) vs rod: a rope only pulls (correct only if too long), a rod keeps both directions. Change the sign check.
  • Angle limits and bending (for stiff cloth, constrain the point two apart).
  • Collisions are just another constraint: if a point is inside a shape, project it to the surface after the distance constraints.
  • Joints in rigid-body engines (hinge, slider, spring) use the same sequential impulse machinery as contacts, applied to velocities instead of positions.

Cloth, hair and soft bodies

A cloth is a grid of points with structural constraints (neighbours), shear constraints (diagonals) and optionally bend constraints. Hair and tails are ropes. Soft bodies add a pressure or volume constraint. The expensive parts are the many iterations and collision, so games simulate the cloth at low resolution, only near the camera, and often only for decoration (capes, flags) that does not affect gameplay.

Choosing: rigid body engine or hand-made?

Use the engine's joints for gameplay-relevant physical objects (a swinging platform, a vehicle). Write a small Verlet system for cosmetic, high-count, or highly controllable things (a rope the player grapples, hair, tentacles, a chain of fish). It is a few dozen lines and you control the cost.

Exercise: design a grappling hook

The player fires a hook that sticks to a wall; a rope connects it to the player, who can swing and reel in.

  • Is it a rope or a rod constraint while swinging? (Rope: only pulls when taut.)
  • Where does the constraint act: on the player's position (Verlet-style: clamp distance to the rope length) or on its velocity (remove the outward component along the rope)? Which feels more controllable?
  • How do you reel in? (Decrease the maximum length over time.)
  • Does the rope need to wrap around corners? (A list of anchor points updated when the line of sight is blocked: your raycast lesson.)
  • Should the rope be a visual Verlet chain while the gameplay uses one distance constraint? (Usually yes: cosmetic detail separate from gameplay.)

Answer key

1. Quick check back ↑

B. Run more constraint-relaxation iterations per step (or use substeps)

Each iteration passes the correction one link further. Few iterations cannot propagate a pin's influence down a long chain.

2. Quick check back ↑

B. Velocity is derived from the positions, so moving a point to satisfy a constraint also corrects its velocity automatically

There is no separate velocity to keep consistent: position is the state.

3. Check 1 back ↑

B. The pinned point does not move; the free point takes the whole correction along the line between them

Anchors are infinitely heavy. Moving only the free end keeps the pin exactly in place.

4. Check 2 back ↑

A. A max-length rope constraint that only pulls when overstretched, ideally with one gameplay distance constraint plus a separate cosmetic Verlet chain for the visual

Ropes constrain only over-length. Gameplay needs one reliable limit while looks can be a cheap visual chain.
