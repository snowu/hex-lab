Hash maps & complexity talk

Most practical problems are a hash map plus a clear invariant.

Always say the complexity out loud and what you trade for it. The 80% pattern: replace a nested loop with a dict or set lookup → O(n²) becomes O(n) time at O(n) space.

# O(n^2): "in" on a list is a linear scan
for a in xs:
    for b in xs:
        ...

# O(n) time, O(n) space
seen = set()
for x in xs:
    if x in seen:
        ...
    seen.add(x)

Know your standard library: dict and set (hash tables; dicts keep insertion order since 3.7), collections.Counter, defaultdict and deque, and heapq. Keys must be hashable: tuples are, lists and dicts are not. And x in some_list is O(n), the most common accidental quadratic.

Answer key

1. Quick check back ↑

C. Set of seen ids: O(n) time, O(n) space

A Set gives O(1) average membership. Mention the memory trade-off, and that with tight memory you might sort or use a Bloom filter (accepting false positives).

2. Latest record wins back ↑

Hint: A dict keeps insertion order, and assigning to an existing key keeps its original position.

Reference solution:

def latest_by_id(events):
    best = {}
    for e in events:
        cur = best.get(e['id'])
        if cur is None or e['ts'] >= cur['ts']:
            best[e['id']] = e
    return list(best.values())

Dicts preserve insertion order (3.7+), and re-assigning an existing key keeps its original position, which gives the ordering for free.

3. Group and count back ↑

Hint: collections.Counter counts for you. Counter.most_common breaks ties by first-seen order, not alphabetically, so sort yourself with a (−count, word) key.

Reference solution:

from collections import Counter

def top_k(words, k):
    counts = Counter(words)
    ranked = sorted(counts.items(), key=lambda kv: (-kv[1], kv[0]))
    return [word for word, _ in ranked[:k]]

When n is huge and k is small, heapq.nsmallest(k, ..., key=...) is O(n log k) instead of sorting everything.
