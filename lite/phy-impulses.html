Collision response with impulses

What happens after two bodies touch: impulses, restitution, friction, mass, and why stacks of boxes are hard.

From "they overlap" to "they bounce"

Detection (collision lesson) tells you that two shapes touch and gives a contact normal n (the direction to push them apart) and a penetration depth. Response decides the new velocities. Modern engines use impulses: an instantaneous change of momentum J. Applying an impulse to a body changes its velocity by J / mass. The unknown is how big the impulse must be.

The normal impulse

Take the relative velocity of body 2 with respect to body 1 along the normal: v_n = (v2 - v1) · n. If v_n > 0 they are already separating: do nothing. Otherwise the impulse that reverses the approach, scaled by the restitution e (0 = no bounce, 1 = perfectly elastic), is

j = -(1 + e) * v_n / (1/m1 + 1/m2)
v1 -= (j / m1) * n
v2 += (j / m2) * n

That is the same formula as the 1-D drill, just along an arbitrary direction. Using inverse mass (1/m) makes immovable bodies trivial: give a wall inverse mass 0 and it never moves, and the formula still works. The complete function below resolves two circles; its test checks that momentum is conserved and the bodies separate.

const std = @import("std");

const Body = struct { x: f32, y: f32, vx: f32, vy: f32, inv_mass: f32, r: f32 };

/// Resolve a collision between two circles: an impulse along the contact normal with restitution e.
fn resolve(a: *Body, b: *Body, e: f32) bool {
    const dx = b.x - a.x;
    const dy = b.y - a.y;
    const dist = @sqrt(dx * dx + dy * dy);
    if (dist == 0 or dist >= a.r + b.r) return false; // not touching
    const nx = dx / dist;
    const ny = dy / dist;
    const vn = (b.vx - a.vx) * nx + (b.vy - a.vy) * ny;
    if (vn > 0) return false; // already separating
    const j = -(1 + e) * vn / (a.inv_mass + b.inv_mass);
    a.vx -= j * a.inv_mass * nx;
    a.vy -= j * a.inv_mass * ny;
    b.vx += j * b.inv_mass * nx;
    b.vy += j * b.inv_mass * ny;
    return true;
}

test "equal masses along x swap velocities when e = 1" {
    var a = Body{ .x = 0, .y = 0, .vx = 3, .vy = 0, .inv_mass = 1, .r = 1 };
    var b = Body{ .x = 1.5, .y = 0, .vx = 0, .vy = 0, .inv_mass = 1, .r = 1 };
    try std.testing.expect(resolve(&a, &b, 1));
    try std.testing.expectApproxEqAbs(@as(f32, 0), a.vx, 1e-5);
    try std.testing.expectApproxEqAbs(@as(f32, 3), b.vx, 1e-5);
}

test "momentum is conserved in an off-centre hit, and a wall (inverse mass 0) does not move" {
    var a = Body{ .x = 0, .y = 0, .vx = 2, .vy = 1, .inv_mass = 1.0 / 2.0, .r = 1 };
    var b = Body{ .x = 1.2, .y = 1.0, .vx = -1, .vy = 0, .inv_mass = 1.0 / 3.0, .r = 1 };
    const px = 2.0 * a.vx + 3.0 * b.vx;
    const py = 2.0 * a.vy + 3.0 * b.vy;
    try std.testing.expect(resolve(&a, &b, 0.5));
    try std.testing.expectApproxEqAbs(px, 2.0 * a.vx + 3.0 * b.vx, 1e-5);
    try std.testing.expectApproxEqAbs(py, 2.0 * a.vy + 3.0 * b.vy, 1e-5);
    var ball = Body{ .x = 0, .y = 0, .vx = 5, .vy = 0, .inv_mass = 1, .r = 1 };
    var wall = Body{ .x = 1.9, .y = 0, .vx = 0, .vy = 0, .inv_mass = 0, .r = 1 };
    try std.testing.expect(resolve(&ball, &wall, 1));
    try std.testing.expectEqual(@as(f32, 0), wall.vx);
    try std.testing.expectApproxEqAbs(@as(f32, -5), ball.vx, 1e-5);
}

Friction

Along the contact tangent t (perpendicular to n) apply a second impulse that opposes sliding: jt = -(v_rel · t) / (1/m1 + 1/m2), but clamped by Coulomb's law: |jt| <= μ * j. So friction can never exceed the friction coefficient times the normal impulse: heavy pressing means strong friction, and a surface can stop sliding completely (static friction) only up to that limit. Engines blend the two bodies' friction values (often by multiplying or taking the geometric mean).

Positional correction

Impulses fix velocities but not overlap that already exists (sinking into the floor, caused by large steps, or by solver error). Push the bodies apart along n a fraction (0.2 to 0.8) of the penetration beyond a small tolerance (the slop, say 0.01 units), split by inverse mass: correction = max(depth - slop, 0) / (1/m1 + 1/m2) * percent. Correcting fully every frame makes objects jitter; ignoring it makes them sink.

Resting contact and stacking: why it is hard

One body resting on another is a contact that must be resolved every step without bouncing. A stack of five boxes couples ten contacts: resolving one disturbs its neighbours. The standard answer is sequential impulses (Erin Catto's Box2D solver): loop over all contacts several times (4 to 10 iterations), each time applying the impulse that makes that contact's relative velocity zero, accumulating impulses and clamping the accumulated total (so a contact can never pull), and reusing last frame's impulses as a starting guess (warm starting). More iterations means stiffer, more stable stacks and more CPU.

Other pieces you will hear about

  • Restitution threshold: below a small closing speed set e = 0, or resting objects micro-bounce forever.
  • Sleeping: bodies that have barely moved for half a second stop being simulated until something touches them. Huge saving, and the reason stacks stay still.
  • Rotation: for shapes that spin, the impulse also changes angular velocity (torque from the contact point), and the denominator gains a term with the moment of inertia. The structure of the formula is identical.
  • Material combination: pairs of materials (ice on metal) need a rule for friction and bounce; most engines combine per-body values.

Drill: Collision response with impulses

Two balls roll along a line and touch. Body 1 is on the left of body 2. Write collide(m1, v1, m2, v2, e) returning their velocities after the hit, where e is the restitution (0 = they stick together, 1 = perfectly bouncy).

If they are not approaching (v1 <= v2) nothing happens: return the velocities unchanged. Otherwise momentum is conserved and the relative speed after the hit is e times the relative speed before, reversed:

v1' = (m1*v1 + m2*v2 + m2*e*(v2 - v1)) / (m1 + m2)
v2' = (m1*v1 + m2*v2 + m1*e*(v1 - v2)) / (m1 + m2)

Starter (Zig):

const std = @import("std");

pub const Pair = struct { v1: f64, v2: f64 };

/// Body 1 is on the left of body 2 and they touch. e = restitution.
pub fn collide(m1: f64, v1: f64, m2: f64, v2: f64, e: f64) Pair {
    _ = m1;
    _ = m2;
    _ = e;
    return .{ .v1 = v1, .v2 = v2 };
}

Answer key

1. Collision response with impulses back ↑

Hint: Check approaching first (v1 > v2). Then it is just the two formulas. The tests verify momentum conservation, energy conservation at e = 1, sticking at e = 0, and the "wall" limit (one body so heavy it does not move).

Real engines (Box2D, Bullet, Godot Physics) solve this with impulses along the contact normal, adding friction along the tangent, and iterate over all contacts several times ("sequential impulses") because resolving one pair disturbs another. A stack of boxes is hard exactly because of that coupling. The e value is usually blended from the two materials (the larger or the product), and below a small closing speed e is forced to 0 so resting objects stop jittering. Erin Catto's GDC "Understanding Constraints" talk is the next step.
