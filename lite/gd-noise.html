Noise, terrain and Wave Function Collapse

Smooth randomness for terrain and textures: value noise, octaves, domain warping, thresholds for caves and biomes, and constraint-based generation.

Why not just random numbers?

Plain random values are white noise: every sample independent, like TV static. Terrain, clouds, water and wood grain are smooth but irregular: nearby points have similar values, far points do not. Coherent noise gives you that: a deterministic function of position (and a seed) that varies smoothly, so you can ask for the value at any (x, y) without generating the rest, and the same seed always gives the same world.

Value noise

The simplest construction: put a pseudo-random value at every integer grid point (a hash of the coordinates and the seed, so no storage), and interpolate between the four surrounding corners. Linear interpolation shows the grid as creases; a smoothstep curve t*t*(3-2t) on the fraction makes it smooth. Lowering the frequency stretches the blobs, raising it makes them smaller.

const std = @import("std");

/// A hash of an integer grid point and a seed, mapped to [0, 1). No tables, no storage: any point can be asked for at any time.
fn hash1(x: i32, seed: u32) f32 {
    var h: u32 = @bitCast(x);
    h = h *% 374761393 +% seed *% 668265263;
    h = (h ^ (h >> 13)) *% 1274126177;
    h ^= h >> 16;
    return @as(f32, @floatFromInt(h & 0xFFFFFF)) / 16777216.0;
}

fn smooth(t: f32) f32 {
    return t * t * (3 - 2 * t);
}

/// 1-D value noise: random values at integers, smoothly blended in between.
fn valueNoise(x: f32, seed: u32) f32 {
    const xi: i32 = @intFromFloat(@floor(x));
    const t = smooth(x - @floor(x));
    const a = hash1(xi, seed);
    const b = hash1(xi + 1, seed);
    return a + (b - a) * t;
}

/// Fractal noise: several octaves, each at double the frequency and a fraction (persistence) of the amplitude, normalised to [0, 1].
fn fbm(x: f32, octaves: u32, persistence: f32, seed: u32) f32 {
    var sum: f32 = 0;
    var amp: f32 = 1;
    var norm: f32 = 0;
    var freq: f32 = 1;
    for (0..octaves) |o| {
        sum += valueNoise(x * freq, seed + @as(u32, @intCast(o))) * amp;
        norm += amp;
        amp *= persistence;
        freq *= 2;
    }
    return sum / norm;
}

test "noise is deterministic, in range and continuous" {
    try std.testing.expectEqual(valueNoise(3.7, 1), valueNoise(3.7, 1));
    try std.testing.expect(valueNoise(3.7, 1) != valueNoise(3.7, 2)); // a different seed gives a different world
    var x: f32 = -20;
    var prev = valueNoise(x, 5);
    while (x < 20) : (x += 0.01) {
        const v = valueNoise(x, 5);
        try std.testing.expect(v >= 0 and v <= 1);
        try std.testing.expect(@abs(v - prev) < 0.02); // no jumps: nearby samples are close
        prev = v;
    }
}

test "adding octaves adds detail but keeps the range" {
    var x: f32 = 0;
    while (x < 50) : (x += 0.37) {
        const v = fbm(x, 5, 0.5, 9);
        try std.testing.expect(v >= 0 and v <= 1);
    }
    // the same position differs between 1 and 5 octaves (the extra octaves contribute)
    try std.testing.expect(fbm(7.3, 1, 0.5, 9) != fbm(7.3, 5, 0.5, 9));
}

Octaves: fractal Brownian motion (fBm)

One octave is smooth blobs. Real terrain has big mountains, then hills, then rocks, then pebbles. Sum several octaves: each has double the frequency (lacunarity 2) and a fraction of the amplitude (persistence, about 0.5), and divide by the total amplitude. The simulation below lets you add octaves and see detail appear; low persistence is smoother, high is rougher.

Perlin and simplex noise

Gradient noise (Perlin, 1983, and the faster, less grid-aligned simplex) puts a random direction at each lattice point instead of a value and blends their influence. It has fewer blocky artefacts than value noise and a more even look. Most engines ship it: Godot's FastNoiseLite (Perlin, simplex, cellular, value) and NoiseTexture2D. Value noise is perfectly good for prototypes and it is what the simulation below uses.

Turning numbers into worlds

  • Height to terrain: bands of the noise value map to water, sand, grass, forest, rock, snow (try the colour option in the simulation). Thresholds are the whole art.
  • Biomes: use two or three independent noises (height, moisture, temperature) and pick the biome from a table of combinations.
  • Caves: threshold a noise field: below 0.45 is rock, above is open. Combine with the cellular-automata smoothing from the procgen lesson for cleaner shapes.
  • Islands: multiply the noise by a falloff that is 1 in the centre and 0 at the edges.
  • Resources and decoration: scatter by a separate noise, so ore appears in clusters rather than uniformly.
  • Textures and effects: clouds, fire, dissolve masks, water flow (the shader lesson).

Domain warping

Distort the input by another noise before sampling: noise(p + k * noise2(p)). Straight, regular features become flowing, organic ones: marble, rivers, alien landscapes. Tick the checkbox in the simulation.

Practicalities

  • Seeds: a seed is just another input to the hash. Derive per-layer seeds from the world seed so layers are independent.
  • Tileable noise: for repeating textures wrap the lattice coordinates (modulo the period).
  • Chunking: because noise is a function of position, an infinite world is generated chunk by chunk as the player moves, with neighbouring chunks matching perfectly.
  • Cost: hash and interpolation per octave per sample. For large maps use a precomputed texture, a compute shader or the engine's native implementation; do not evaluate 10 octaves for every tile every frame.
  • Looks matter more than maths: tune frequency, octaves and the thresholds by eye on screen, and pin the seed while you tune.

Wave Function Collapse

Noise makes organic shapes but cannot guarantee that a river tile connects to another river tile. Wave Function Collapse (WFC) generates grids where local rules always hold, from an example or a tile set with adjacency constraints (which tile edges match):

  1. Every cell starts as a superposition: any tile possible.
  2. Pick the cell with the lowest entropy (fewest remaining possibilities) and collapse it to one tile (random, weighted).
  3. Propagate: remove from its neighbours the tiles that no longer fit, and keep propagating until nothing changes.
  4. Repeat until every cell is decided. If some cell has no options left (a contradiction), backtrack or restart.

It is excellent for towns, dungeons, textures and decorative layers, because the output obeys the tile rules and looks varied. Its weakness is global structure: it knows nothing about reachability or pacing, so combine it with the validation step (flood fill, constraints on start and exit) or use it to dress up a layout made by another method.
