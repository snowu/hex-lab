Pathfinding in depth

A* properly: open and closed sets, heuristics, grids vs navmeshes, smoothing, hierarchies and budgeting path requests.

A* in one paragraph

A* explores the map starting from the start node, always expanding the node with the smallest f = g + h, where g is the cost already paid to get there and h is a heuristic estimate of the cost still to go. Dijkstra is the same with h = 0 (it spreads out evenly), breadth-first search is Dijkstra with unit costs. A good heuristic makes A* head toward the goal and expand far fewer nodes.

The data structures

  • Open set: nodes discovered but not expanded, ordered by f. A binary heap (priority queue) makes "take the best" O(log n). For tiny maps an array scan is fine.
  • Closed set (or a per-node state): nodes already expanded. Use arrays indexed by node id, not hash sets, for speed on grids.
  • Parent links: each node remembers where it was reached from, so the path is rebuilt backwards from the goal.
  • g scores: if a cheaper route to a node is found later, update its g and parent (and its position in the heap).

Heuristics

MovementAdmissible heuristic
4 directions, cost 1Manhattan distance |dx| + |dy|
8 directions, diagonal cost √2Octile distance: max(dx,dy) + (√2 − 1)·min(dx,dy)
Any direction (a navmesh)Euclidean distance

The heuristic must never overestimate (be admissible) for the result to be the shortest path. Multiplying it by a weight above 1 ("weighted A*") finds paths faster that are at most that much longer, a very common game trade. A perfect-looking tie-break: prefer larger g among equal f to avoid expanding a plateau of equal-cost nodes.

const std = @import("std");

const W = 8;
const H = 6;
const INF = std.math.maxInt(u32);

/// A* on a 4-connected grid with Manhattan distance. '#' is a wall. Returns the length of the shortest path, or null.
/// (The open set is scanned linearly to keep the code short; a real implementation uses a binary heap.)
fn astar(grid: []const []const u8, start: [2]usize, goal: [2]usize, expanded: *usize) ?u32 {
    var g: [W * H]u32 = @splat(INF);
    var closed: [W * H]bool = @splat(false);
    var open: [W * H]bool = @splat(false);
    const s = start[1] * W + start[0];
    const t = goal[1] * W + goal[0];
    g[s] = 0;
    open[s] = true;
    expanded.* = 0;
    while (true) {
        var cur: ?usize = null;
        var best: u32 = INF;
        for (0..W * H) |i| {
            if (!open[i]) continue;
            const x = i % W;
            const y = i / W;
            const h: u32 = @intCast(@abs(@as(i32, @intCast(x)) - @as(i32, @intCast(goal[0]))) + @abs(@as(i32, @intCast(y)) - @as(i32, @intCast(goal[1]))));
            const f = g[i] + h;
            if (f < best or (f == best and g[i] > g[cur.?])) {
                best = f;
                cur = i;
            }
        }
        const c = cur orelse return null;
        if (c == t) return g[c];
        open[c] = false;
        closed[c] = true;
        expanded.* += 1;
        const cx: i32 = @intCast(c % W);
        const cy: i32 = @intCast(c / W);
        for ([_][2]i32{ .{ 1, 0 }, .{ -1, 0 }, .{ 0, 1 }, .{ 0, -1 } }) |d| {
            const nx = cx + d[0];
            const ny = cy + d[1];
            if (nx < 0 or ny < 0 or nx >= W or ny >= H) continue;
            if (grid[@intCast(ny)][@intCast(nx)] == '#') continue;
            const n: usize = @intCast(ny * W + nx);
            if (closed[n]) continue;
            if (g[c] + 1 < g[n]) {
                g[n] = g[c] + 1;
                open[n] = true;
            }
        }
    }
}

const map = [_][]const u8{
    "........",
    ".######.",
    ".#....#.",
    ".#.##.#.",
    ".#....#.",
    "........",
};

test "A* finds the same shortest length as exhaustive search, expanding few nodes on open ground" {
    var n: usize = 0;
    try std.testing.expectEqual(@as(?u32, 7), astar(&map, .{ 0, 0 }, .{ 7, 0 }, &n));
    try std.testing.expect(n <= 10); // goes almost straight there
    try std.testing.expectEqual(@as(?u32, 11), astar(&map, .{ 0, 0 }, .{ 3, 2 }, &n)); // down the left side, along the bottom and up into the room
    const blocked = [_][]const u8{ "..#.....", "..#.....", "..#.....", "..#.....", "..#.....", "..#....." };
    try std.testing.expectEqual(@as(?u32, null), astar(&blocked, .{ 0, 0 }, .{ 7, 5 }, &n));
}

Grids vs navigation meshes

  • Grid: simple, great for tile games and strategy. Paths follow cell centres and look blocky: smooth them. Large open worlds produce huge grids (memory, search cost).
  • Navigation mesh (navmesh): the walkable area as a set of convex polygons with adjacency. Far fewer nodes than a grid, supports any shape and angle. Search runs over the polygons, then the funnel algorithm ("string pulling") pulls the path tight around corners to give a straight, natural route. This is what Godot, Unity and Unreal use for 3D and for non-grid 2D.
  • Waypoint graphs: hand-placed nodes and links; cheap and controllable (racing lines, patrol routes), and tedious to cover large areas.

Making paths look good

  • Smoothing: remove waypoints that a straight line of sight can skip (raycast between non-adjacent waypoints), then optionally round corners.
  • Agent radius: inflate obstacles by the agent's size so wide characters do not clip corners (navmeshes bake this).
  • Costs: different terrains cost different amounts (mud 3, road 1); danger zones cost more so AI avoids them without forbidding them.
  • Tie-breaking: many equal-length paths exist on a grid; add a tiny bias (prefer straight lines) to avoid zig-zags.

Scaling up

  • Hierarchical pathfinding: precompute connectivity between regions (rooms, chunks) and search the coarse graph first, then refine locally.
  • Jump point search: on uniform-cost grids, skips over symmetric paths and is often an order of magnitude faster than A*.
  • Flow fields (integration field plus direction field) for many agents sharing a goal.
  • Time-sliced search: give pathfinding a per-frame budget (a few milliseconds), keep searches resumable, and queue requests. Agents move toward the best partial path in the meantime. Cancel requests whose agent died or changed its mind.
  • Cache and share: agents in the same region heading to the same place can reuse paths.

Dynamic worlds

Doors open, bridges collapse, crates move. Options: mark nodes blocked and re-run affected searches, use D* Lite (incremental replanning for changing maps), or let local avoidance handle small obstacles and replan only when the path is truly blocked. Never replan every frame.

Common bugs

  • The goal is inside an obstacle or off the navmesh: snap it to the nearest valid point first.
  • Paths that cut corners through walls: obstacle inflation missing.
  • Agents vibrating at the goal: use arrive and an acceptance radius, not exact equality.
  • Stuck on a door: the door's collision is in the navmesh but the agent cannot open it; model it as a node with a cost or an "action" link.

Answer key

1. Quick check back ↑

B. Octile distance

Manhattan overestimates when diagonals are allowed (inadmissible). Octile is exact for an empty 8-way grid. Twice anything may overestimate too.

2. Quick check back ↑

B. A navigation mesh of convex polygons with funnel smoothing

Navmeshes cover large areas with few nodes and give natural, smooth routes.

3. Quick check back ↑

B. Queue the requests and time-slice searches with a per-frame budget, serving the nearest or most urgent first

Spread the work over frames. Agents can move on a partial or old path while they wait.

4. Check 1 back ↑

B. It may overestimate the remaining cost, breaking admissibility, so the path is no longer guaranteed shortest

An admissible heuristic never overestimates; weighting above 1 trades optimality for speed by design.

5. Check 2 back ↑

D. Obstacle inflation by the agent radius: paths must be planned for the body size, not a point

Inflating obstacles (or baking radius into the navmesh) keeps wide bodies off corners they cannot fit around.
