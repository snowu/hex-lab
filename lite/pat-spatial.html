Spatial partitioning

Grids, quadtrees and bounding volume hierarchies: finding what is near without looking at everything.

The problem

"Which enemies are within 200 pixels of the player?", "what does this bullet collide with?", "which objects are visible?". The naive answer checks every object: O(n) per query, O(n²) for all pairs. With 5,000 objects that is 12 million pair checks per frame. Spatial partitioning stores objects in a structure organised by position so a query only visits the neighbourhood.

Uniform grid (and spatial hash)

Divide space into equal cells. Each cell holds a list of the objects inside it. A query looks at the cells the query region overlaps. Insertion is O(1), queries are proportional to the number of nearby objects. Variations: a fixed 2D array (fast; needs bounded space) or a hash map from cell coordinates to a list (unbounded space, no empty-cell memory). The drill in the performance lesson builds one.

  • Cell size is the knob: about the typical query radius or object size. Too small: a query touches many cells and objects span several. Too large: each cell holds too many objects.
  • Moving objects: rebuild every frame (simple, often the fastest for dynamic crowds) or move an object between cells only when it crosses a boundary.
  • Big objects (a huge boss) overlap many cells; insert it into all of them or into a separate "large objects" list.
  • Weak when density is very uneven (a crowd in one corner of a big empty map).

Quadtree (octree in 3D)

A tree that subdivides a region into four quadrants only where there are many objects. Dense areas get deep, fine cells; empty areas stay one big cell. Queries descend only into quadrants that overlap the query. Good for uneven density and static or slowly moving objects; costlier to update than a grid when everything moves each frame. A loose quadtree lets nodes overlap by a margin so a moving object rarely needs to change nodes.

Bounding volume hierarchy (BVH)

A tree where each node stores a bounding box of everything below it, built from the objects rather than from fixed space. Queries skip a whole subtree when its box misses. This is what most physics engines use for their broadphase (Box2D's dynamic tree) and what ray tracers use. It handles objects of very different sizes well, and supports dynamic updates by refitting boxes.

Sweep and prune

Sort object bounds along one axis and only compare overlapping neighbours in the sorted list. When objects move a little each frame, the list is almost sorted already, so re-sorting is cheap. Used in physics engines for large scenes with mostly coherent motion.

Choosing

SituationReach for
Many similar-sized moving objects (bullets, crowd)Uniform grid / spatial hash, rebuilt each frame
Very uneven density, mostly staticQuadtree
Objects of very different sizes, raycasts, dynamic scenesBVH / dynamic tree
A few hundred objectsBrute force. Do not add a structure you cannot justify with a measurement.

Engines already include a broadphase (Godot, Box2D, Jolt). Build your own for non-physics queries: AI perception, crowd avoidance, pickups in range, "everything inside this explosion".

A quadtree in Zig (insert and query)

const std = @import("std");

const Rect = struct { x: f32, y: f32, w: f32, h: f32 };

fn overlaps(a: Rect, b: Rect) bool {
    return a.x < b.x + b.w and b.x < a.x + a.w and a.y < b.y + b.h and b.y < a.y + a.h;
}

/// A tiny point quadtree with fixed capacity per leaf and a depth limit, no allocation (children live in a flat array).
const Quad = struct {
    const cap = 4;
    const max_nodes = 64;

    const Node = struct { bounds: Rect, pts: [cap][2]f32 = undefined, n: usize = 0, kids: ?usize = null };

    nodes: [max_nodes]Node = undefined,
    count: usize = 1,

    fn init(bounds: Rect) Quad {
        var q = Quad{};
        q.nodes[0] = .{ .bounds = bounds };
        return q;
    }

    fn insert(self: *Quad, node: usize, x: f32, y: f32, depth: u8) bool {
        const b = self.nodes[node].bounds;
        if (x < b.x or y < b.y or x >= b.x + b.w or y >= b.y + b.h) return false;
        if (self.nodes[node].kids == null) {
            if (self.nodes[node].n < cap or depth >= 3 or self.count + 4 > max_nodes) {
                if (self.nodes[node].n == cap) return false; // full at max depth: a real tree would use an overflow list
                const n = self.nodes[node].n;
                self.nodes[node].pts[n] = .{ x, y };
                self.nodes[node].n += 1;
                return true;
            }
            self.split(node);
        }
        const k = self.nodes[node].kids.?;
        for (0..4) |i| if (self.insert(k + i, x, y, depth + 1)) return true;
        return false;
    }

    fn split(self: *Quad, node: usize) void {
        const b = self.nodes[node].bounds;
        const hw = b.w / 2;
        const hh = b.h / 2;
        const first = self.count;
        self.count += 4;
        self.nodes[first] = .{ .bounds = .{ .x = b.x, .y = b.y, .w = hw, .h = hh } };
        self.nodes[first + 1] = .{ .bounds = .{ .x = b.x + hw, .y = b.y, .w = hw, .h = hh } };
        self.nodes[first + 2] = .{ .bounds = .{ .x = b.x, .y = b.y + hh, .w = hw, .h = hh } };
        self.nodes[first + 3] = .{ .bounds = .{ .x = b.x + hw, .y = b.y + hh, .w = hw, .h = hh } };
        self.nodes[node].kids = first;
        const old = self.nodes[node];
        self.nodes[node].n = 0;
        for (old.pts[0..old.n]) |p| _ = self.insert(node, p[0], p[1], 99); // depth 99: reinsert into the children
    }

    /// How many points are inside the query rectangle. Subtrees whose bounds miss the query are skipped.
    fn countIn(self: *const Quad, node: usize, q: Rect) usize {
        if (!overlaps(self.nodes[node].bounds, q)) return 0;
        var total: usize = 0;
        for (self.nodes[node].pts[0..self.nodes[node].n]) |p| {
            if (p[0] >= q.x and p[0] < q.x + q.w and p[1] >= q.y and p[1] < q.y + q.h) total += 1;
        }
        if (self.nodes[node].kids) |k| for (0..4) |i| {
            total += self.countIn(k + i, q);
        };
        return total;
    }
};

test "a query only counts the points inside it" {
    var q = Quad.init(.{ .x = 0, .y = 0, .w = 100, .h = 100 });
    var i: u32 = 0;
    while (i < 30) : (i += 1) {
        const x: f32 = @floatFromInt((i * 37) % 100);
        const y: f32 = @floatFromInt((i * 61) % 100);
        try std.testing.expect(q.insert(0, x, y, 0));
    }
    try std.testing.expectEqual(@as(usize, 30), q.countIn(0, .{ .x = 0, .y = 0, .w = 100, .h = 100 }));
    var brute: usize = 0;
    i = 0;
    while (i < 30) : (i += 1) {
        const x: f32 = @floatFromInt((i * 37) % 100);
        const y: f32 = @floatFromInt((i * 61) % 100);
        if (x >= 10 and x < 40 and y >= 20 and y < 70) brute += 1;
    }
    try std.testing.expectEqual(brute, q.countIn(0, .{ .x = 10, .y = 20, .w = 30, .h = 50 }));
}

Answer key

1. Quick check back ↑

B. A uniform grid or spatial hash rebuilt every frame

Rebuilding a grid is O(n) with tiny constants, and equal-sized movers suit a single cell size.

2. Quick check back ↑

B. Use a loose quadtree (nodes overlap by a margin) or switch to a rebuilt grid

Loose nodes let small moves stay in the same node. For fully dynamic data a grid rebuild is often cheaper than maintaining a tree.

3. Quick check back ↑

B. Measure first: at that size brute force is probably fine, and a structure adds code and bugs for no gain

Optimisation without a measurement is guessing. Small n does not need acceleration structures.

4. Check 1 back ↑

B. About the typical query radius or object size: too small touches many cells and splits objects, too large packs too many objects per cell

Cell size balances cells visited against objects per cell. The query radius is the natural scale.

5. Check 2 back ↑

A. Quadtree for the static uneven forest since empty areas stay coarse, and a rebuilt grid or spatial hash for the many similar-sized movers

Quadtrees adapt to uneven static density; grids with O(1) insert and per-frame rebuild suit dynamic crowds.
