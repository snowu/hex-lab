Collision detection and response

AABB and circle tests, push-out, broad and narrow phase, and why fast things tunnel through walls.

Two phases

Testing every pair is O(n²). So collision is split in two:

  1. Broad phase: cheaply find pairs that might touch, using a grid, spatial hash or tree (see the performance lesson).
  2. Narrow phase: precise tests on those pairs, then response: separate them, bounce, apply damage.

Shapes, cheapest first

  • Circle vs circle: distance² < (r1 + r2)². No square root. Characters often use a capsule or circle for smooth sliding.
  • AABB (axis-aligned bounding box): overlap if the intervals overlap on both axes. Tiles and platformer characters live here.
  • OBB / convex polygons: the separating axis theorem (SAT). If you can find any axis along which the shapes' projections do not overlap, they do not collide. Test the edge normals.

Response: the minimum translation

When two boxes overlap, push one out along the axis with the smallest penetration. That is why a character landing on a floor is pushed up rather than sideways. For tile maps the robust trick is to move on one axis, resolve, then move on the other axis. That gives clean wall sliding and no corner snagging.

Tunneling

Collision tests happen once per step, on positions. If something moves further in one step than the thickness of what it should hit, no step ever sees them overlapping, and it passes straight through. The fixes, cheapest first:

  1. Limit the maximum speed, or make walls thicker.
  2. Substep: run the physics several times per frame.
  3. Swept (continuous) collision: test the whole path from old to new position and find the time of first impact (you implement 1-D version in the drill). Engines call this CCD.
  4. Ray/shape casts for bullets: do not simulate a bullet as a moving body at all.

Simulation: A bullet and a thin wall

A bullet flies at a wall that is only a few pixels thick. Each ghost is where the bullet is at the end of a 60 Hz physics step. The check either tests only those positions (discrete) or the full path between them (swept).

Try this in the full app:

  • At low speed the discrete test hits the wall.
  • Raise the speed until the bullet tunnels: the ghosts jump over the wall without ever overlapping it.
  • Tick swept test at the same speed: the hit is found exactly, the bullet stops at the wall face.
  • Find the speed at which discrete tunnelling starts and compare with (wall width + bullet width) × 60.

Drill: AABB overlap and push-out

Rectangles are {x, y, w, h} with y growing downward (screen coordinates).

  • overlaps(a, b): true only if the rectangles share area. Touching edges do not count.
  • push_out(a, b): the smallest translation that moves a so it no longer overlaps b, along the axis of least penetration. The sign points away from b (compare the rectangle centres). Returns (0, 0) when they do not overlap. If both axes tie, resolve on x.

Starter (Zig):

const std = @import("std");

pub const Rect = struct { x: f32, y: f32, w: f32, h: f32 };
pub const Vec2 = struct { x: f32, y: f32 };

pub fn overlaps(a: Rect, b: Rect) bool {
    _ = a;
    _ = b;
    return false;
}

/// How far to move a so it stops overlapping b (zero if it does not).
pub fn pushOut(a: Rect, b: Rect) Vec2 {
    _ = a;
    _ = b;
    return .{ .x = 0, .y = 0 };
}

Drill: Swept collision time (no tunneling)

A box of width size with left edge at pos moves right by dist this frame. A wall's left face is at wall_left.

Return the fraction t in [0, 1] of this frame's movement at which the box's right edge first touches the wall, or "nothing" if it does not reach the wall this frame, if the wall is already behind or overlapping the box (gap < 0), or if dist <= 0. Touching already (gap == 0) is t = 0.

Unlike testing only the end position, a fast box cannot skip over a thin wall.

Starter (Zig):

const std = @import("std");

pub fn sweepHit(pos: f32, size: f32, dist: f32, wall_left: f32) ?f32 {
    _ = pos;
    _ = size;
    _ = dist;
    _ = wall_left;
    return null;
}

In Godot

  • CharacterBody2D + move_and_slide() for player-controlled things: you set velocity, the engine handles sweeps, slopes and sliding.
  • RigidBody2D for things the physics engine drives (crates, balls). Turn on continuous CD for fast ones.
  • Area2D for triggers (pickups, damage zones, hitboxes): overlap events, no response.
  • Collision layers and masks: layer is "what I am", mask is "what I look for". Player bullets should be on a layer enemies' hurtboxes scan, and not hit the player. Set this up before you have thirty object types.

Answer key

1. AABB overlap and push-out back ↑

Hint: Penetration on x = min(a.right, b.right) - max(a.left, b.left); same for y. Pick the smaller (x on ties). Push negative if a's centre is left of (above) b's, else positive.

Resolving along the least-penetration axis is why a character standing on a floor gets pushed up, not sideways. For tile maps the usual trick is to move and resolve one axis at a time (x then y), which also gives clean wall sliding.

2. Swept collision time (no tunneling) back ↑

Hint: gap = wall_left - (pos + size). If dist <= 0 or gap < 0 there is no hit. Otherwise t = gap / dist, and there is no hit if t > 1.

In 2D this becomes ray-vs-expanded-AABB (Minkowski sum), and in engines it is continuous collision detection (Godot: continuous_cd on RigidBody2D, or shape casts for bullets). Cheap alternatives: cap the speed, or substep the physics. Only the left face matters here because the box moves right; a box moving left would use the wall's right face.

3. Quick check back ↑

B. Push 3 px horizontally, away from the other box

Resolve along the axis of least penetration: the smallest move that separates them.

4. Quick check back ↑

B. It moves 50 px per step, more than the wall is thick, so no step ever overlaps it (tunneling)

3000 / 60 = 50 px per step. Use swept/continuous collision, a raycast for the bullet, or substeps.

5. Check 1 back ↑

A. No, an AABB overlap needs the intervals to overlap on both axes

AABB collision requires overlap on every axis; a gap on any one axis means no contact.

6. Check 2 back ↑

B. Test the whole path from old to new position with a swept test or raycast, or substep the physics

Tunneling happens because discrete steps jump over the wall; continuous tests find the time of first impact along the path.
