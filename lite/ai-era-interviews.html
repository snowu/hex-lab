Interviewing in the AI era

What changed, how to use AI honestly, and how to show judgment.

Code generation is cheap now, so interviews are shifting toward what is still scarce: judgment, verification, system thinking, and communication. Expect any of:

  • AI-allowed coding rounds: you use an assistant; they watch how you prompt, review, and test.
  • Review-the-diff rounds: find the bug in plausible-looking (often AI-written) code.
  • Deeper “why” follow-ups on solutions you wrote, to check you understand them.
  • Design and incident discussions that are hard to fake.

The rules for using AI in an interview

  1. Follow the stated policy. If it is unclear, ask. Never use hidden tools.
  2. Think first, then prompt. State the approach and edge cases before generating code.
  3. Treat output as a junior PR. Read every line, run it, test the boundaries.
  4. Narrate verification: “It handles the happy path. Let me check empty input, duplicates, and concurrent calls.”
  5. Own the result. You must be able to explain every line.

AI-assisted take-homes

Many companies now allow, or assume, AI on take-home tasks. That raises the bar on everything around the code:

  • Disclose how you used it in the README: what you generated, what you rewrote, what you verified. Hidden use that surfaces in the follow-up call ends the process.
  • Show the process with small, meaningful commits instead of one “initial commit” of 3,000 lines.
  • Write the decisions down: the trade-offs, what you left out on purpose, what you would do with more time. This is the part AI cannot do for you and the part reviewers read most closely.
  • Tests that matter: edge cases and failure paths, not a wall of generated happy-path tests.
  • Expect a live extension: “add pagination to your solution, now, while we watch”. If you cannot change your own code without the assistant, it shows.

Agentic tools in a live round

If the round allows a coding agent that edits files and runs commands, the evaluation moves further toward direction and review: how precisely you describe the task, whether you give it the tests first, whether you read the diff before accepting it, and how fast you notice when it has gone the wrong way. Keep the agent on small steps you can verify, and say what you are checking as you go.

Answer key

1. Spot and fix the AI bug back ↑

Hint: The range stops one page too early (len(items) - size). And decide what a size of 0 or a negative number should do: slicing is forgiving, so bad input silently returns garbage unless you check it.

Reference solution:

def chunk(items, size):
    if not isinstance(size, int) or size <= 0:
        raise ValueError('size must be a positive integer')
    return [items[i:i + size] for i in range(0, len(items), size)]

Generated code looked right. Boundaries (off-by-one, empty input, invalid input) are exactly where it fails, so test them first. Python is forgiving (slices never raise), which makes silent wrong answers easy.
