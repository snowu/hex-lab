Sagas, circuit breakers, timeouts

Coordinating steps across services, and protecting yourself from slow dependencies.

Sagas

No distributed transaction? Model a business process as a series of local transactions, each with a compensating action. Orchestration (a coordinator drives the steps, easier to reason about and observe) vs choreography (services react to events, loosely coupled but the flow is implicit).

reserve funds -> initiate payment -> await bank status -> book ledger
        on failure: release funds <- cancel payment <- ...

Compensation is semantic, not a rollback: you cannot unsend an email, you send a correction.

Circuit breaker

States: closed (normal) → after N failures → open (fail fast for a cooldown) → half-open (let one probe through; success closes, failure re-opens). It stops you from queueing up threads against a dead dependency and gives it room to recover.

Timeouts are the foundation. Every outbound call needs one, shorter than your caller’s timeout (deadline propagation), or one slow bank will exhaust your connection pool.

Try this in the full app:

  • While it is OPEN keep sending: requests are rejected instantly and the dependency is never touched.
  • Wait for the cooldown, bring the dependency UP and send once: the probe succeeds and the breaker closes.
  • Repeat, but leave the dependency down during the probe: it goes straight back to OPEN.

Challenge (Python): Circuit breaker

Implement class CircuitBreaker with __init__(failure_threshold=3, cooldown=1.0, now=time.monotonic) and async def call(fn) (fn is an async function with no arguments).

  • Closed: run fn. Count consecutive failures; a success resets the count. At failure_threshold failures → open.
  • Open: raise CircuitOpenError('circuit open') immediately, without calling fn, until cooldown seconds have passed.
  • After the cooldown: half-open. Allow one trial call: success → closed, failure → open again (cooldown restarts).

Answer key

1. Circuit breaker back ↑

Hint: Track a state ("closed" / "open" / "half"), the consecutive failure count, and the time it opened. In call(): if open and the cooldown has passed, move to half. In half-open, a failure opens the breaker immediately. Catch Exception, record, then re-raise.

Reference solution:

import time

class CircuitOpenError(Exception):
    pass

class CircuitBreaker:
    def __init__(self, failure_threshold=3, cooldown=1.0, now=time.monotonic):
        self.failure_threshold = failure_threshold
        self.cooldown = cooldown
        self.now = now
        self.state = 'closed'
        self.failures = 0
        self.opened_at = 0.0

    async def call(self, fn):
        if self.state == 'open':
            if self.now() - self.opened_at < self.cooldown:
                raise CircuitOpenError('circuit open')
            self.state = 'half'
        try:
            result = await fn()
        except Exception:
            self.failures += 1
            if self.state == 'half' or self.failures >= self.failure_threshold:
                self.state = 'open'
                self.opened_at = self.now()
            raise
        self.state = 'closed'
        self.failures = 0
        return result

Production breakers add: a single probe in half-open (limit concurrency), failure-rate windows instead of consecutive counts, slow-call thresholds, per-dependency instances (per bank!), and metrics on state changes.

Compensations run in reverse, must be idempotent (they may be retried), and the saga state must be persisted so it survives crashes.
