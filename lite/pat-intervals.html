Intervals & scheduling

Sort by start, sweep, and use a heap of end times.

Interval problems become easy once the input is sorted by start time. Decide up front whether intervals are closed [a, b] or half-open [a, b), because that decides whether touching intervals overlap. Booking systems normally use half-open.

  • Merge: sort, then extend the last merged interval or start a new one.
  • Count overlaps / resources: a min-heap of end times (or a sweep over +1/−1 events).
  • Insert / remove: binary search the position, then merge locally.

Answer key

1. Merge intervals back ↑

Hint: Sort by start. Walk through: if the next interval starts at or before the current end, extend the end with max(end, next_end); otherwise start a new one. Copy the lists you append so you do not alias the input.

Reference solution:

def merge_intervals(intervals):
    merged = []
    for start, end in sorted(intervals):
        if merged and start <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])
    return merged

sorted() returns a new list, but the inner lists are still the input objects. Here we append fresh [start, end] lists, so mutating merged[-1] never touches the input. Think about whether the half-open or closed interpretation applies in the real problem (booking systems usually use half-open).

2. Minimum meeting rooms back ↑

Hint: Sort by start time and keep a min-heap of end times for the rooms in use. If the earliest-ending room is free (end <= next start), reuse it (pop) before pushing the new end. The heap size at the end is the answer.

Reference solution:

import heapq

def min_rooms(meetings):
    ends = []  # min-heap of end times of rooms currently in use
    for start, end in sorted(meetings):
        if ends and ends[0] <= start:
            heapq.heapreplace(ends, end)
        else:
            heapq.heappush(ends, end)
    return len(ends)

The alternative is a sweep over sorted start and end events. The same shape appears in capacity planning, booking engines, and "max concurrent connections" questions.
