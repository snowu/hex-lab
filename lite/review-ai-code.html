Reviewing AI-written code

Recurring failure patterns and a checklist.

Generated code is fluent and confident, so review fatigue is the risk. Patterns to hunt:

  • Boundary bugs: off-by-one, empty input, None / empty values, unicode, timezones.
  • Hallucinated APIs: a method or option that does not exist, or existed in an older version.
  • Money & time: floats for currency, local time instead of UTC, DST.
  • Security: string-built SQL, missing authorisation checks (only authentication), secrets in logs, SSRF, unsafe deserialisation.
  • Concurrency: check-then-act races, missing awaits, fire-and-forget tasks, unbounded asyncio.gather, mutable default arguments.
  • Over-engineering: abstractions nobody asked for. Delete them.
  • Tests that assert the implementation rather than the behaviour, or mock away the thing under test.

Working with coding agents

Agents that edit files, run tests and open pull requests change the bottleneck from writing code to specifying and reviewing it. What separates a productive team from a fast-but-fragile one:

  • Spec first. A short written goal, constraints and acceptance tests before the agent starts. Vague tasks produce plausible, wrong diffs.
  • Small diffs. Ask for one change per PR. A 2,000-line agent diff is not reviewable, so it will not really be reviewed.
  • Tests as the contract. Write or approve the tests yourself; let the agent make them pass. Watch for agents weakening or deleting tests to get to green.
  • Same bar as humans. CI, code review and ownership rules apply unchanged. “The AI wrote it” is never an answer in an incident review.
  • Guard the blast radius. Agents get sandboxes and scoped credentials, never production secrets or direct deploy rights.

Answer key

1. Quick check back ↑

B. Floating-point arithmetic on currency (0.1 + 0.2 ≠ 0.3); use integer minor units (cents) or a decimal type

Represent money as integer minor units (or decimal.Decimal) and round explicitly with a defined rule.

2. Quick check back ↑

B. An authorisation check that the authenticated user owns or may access account :id (IDOR / BOLA)

Authentication ≠ authorisation. Without an ownership check any logged-in user can read any account by changing the id. A top-10 API vulnerability (BOLA).

3. Review this AI-written endpoint back ↑

Hint: One line builds a query from user input. The other writes something secret to the logs.

  • Line 4: An f-string builds the SQL, so it is injectable. It also queries by whatever id the caller supplies, with no check that the logged-in user owns that account, which is broken object-level authorisation (BOLA/IDOR). Use parameterised queries and filter by the caller's accounts.
  • Line 5: Logs the Authorization header, so bearer tokens end up in log storage. Never log credentials or tokens, and keep PII out of application logs.

4. Plausible but wrong helpers back ↑

Hint: Think about when Python evaluates default argument values, and what an empty list does to the division.

  • Line 1: A mutable default argument is created once, when the function is defined, and shared by every call: add_tag("a") then add_tag("b") returns ["a", "b"]. Use tags=None and create the list inside the function.
  • Line 6: Raises ZeroDivisionError on an empty list. Decide what the average of nothing should be (None, 0, or a clear error) and handle it explicitly.

5. Fix the AI-written discount function back ↑

Hint: Use decimal.Decimal and quantize(Decimal(1), rounding=ROUND_HALF_UP). Build the Decimal from str(percent) so 33.5 does not carry binary-float noise.

Reference solution:

import math
from decimal import Decimal, ROUND_HALF_UP

def apply_discount(price_cents, percent):
    if not isinstance(price_cents, int) or isinstance(price_cents, bool) or price_cents < 0:
        raise ValueError('price must be a non-negative integer number of cents')
    if not isinstance(percent, (int, float)) or not math.isfinite(percent) or not 0 <= percent <= 100:
        raise ValueError('percent must be between 0 and 100')
    result = Decimal(price_cents) * (100 - Decimal(str(percent))) / 100
    return int(result.quantize(Decimal(1), rounding=ROUND_HALF_UP))

round(52.5) is 52 in Python (round-half-to-even), which is a classic money bug. Use Decimal with an explicit rounding mode, or integer arithmetic, and agree the rule with finance.

Hallucinated or version-wrong APIs are a classic generation failure. Verify every unfamiliar call against the version you actually run.
