RAG & evaluation

Chunking, similarity search, and how you know it works.

RAG (retrieval-augmented generation): split documents into chunks → embed each into a vector → at question time embed the query, fetch the top-k most similar chunks, put them in the prompt. Quality is mostly decided by chunking and retrieval, not the generator.

cosine(a, b) = (a · b) / (|a| · |b|)

Evaluate or you are guessing

  • Build a small golden set (30-100 real questions with expected sources/answers) before tuning anything.
  • Measure retrieval (recall@k: was the right chunk in the top k?) separately from generation (faithfulness to context, correctness).
  • LLM-as-judge is useful but must itself be spot-checked by humans. Run evals in CI so prompt changes cannot silently regress.

Answer key

1. Cosine similarity & top-k retrieval back ↑

Hint: dot / (|a| * |b|) with math.sqrt, guarding the zero case. Then sort the docs by similarity, descending, and slice k. (At scale: approximate nearest-neighbour indexes such as HNSW.)

Reference solution:

import math

def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    if na == 0 or nb == 0:
        return 0.0
    return dot / (na * nb)

def top_k_docs(query_vec, docs, k):
    ranked = sorted(docs, key=lambda d: cosine(query_vec, d['vec']), reverse=True)
    return [d['id'] for d in ranked[:k]]

In production you would use numpy and normalise vectors once so similarity becomes a dot product. For millions of vectors use an ANN index (HNSW, IVF) rather than a full scan.

2. Chunk text with overlap back ↑

Hint: step = size - overlap. Walk i in steps, take text[i:i + size], and stop as soon as i + size >= len(text).

Reference solution:

def chunk_text(text, size, overlap):
    if overlap >= size:
        raise ValueError('overlap must be smaller than size')
    step = size - overlap
    chunks = []
    for i in range(0, len(text), step):
        chunks.append(text[i:i + size])
        if i + size >= len(text):
            break
    return chunks

In practice split on semantic boundaries (headings, paragraphs) first, keep metadata (source, section) with each chunk, and test the chunk size against your retrieval evals rather than guessing.
