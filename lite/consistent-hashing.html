Deep dive: consistent hashing

How to spread keys over nodes without reshuffling everything. Implement it.

With hash(key) % N, adding a node remaps almost every key, which is a cache disaster. Consistent hashing places nodes (and many virtual nodes per node) on a ring; a key belongs to the first node clockwise from its hash. Adding or removing a node moves only ~1/N of the keys.

  • Virtual nodes even out load and let you weight bigger machines.
  • Used by Dynamo-style stores, memcached clients, and many load balancers.

  • Set virtual nodes to 1 and look at the spread: some nodes get far more keys than others.
  • Raise virtual nodes to 100 and the load evens out.

Answer key

1. Implement a hash ring back ↑

Hint: Keep self.points as a sorted list of (hash, node) tuples. get_node: bisect_left for (fnv1a(key),), wrapping to index 0 when you run off the end. Virtual node i of a node hashes the string f"{name}#{i}".

Reference solution:

import bisect

def fnv1a(text):  # 32-bit FNV-1a
    h = 2166136261
    for ch in text:
        h ^= ord(ch)
        h = (h * 16777619) & 0xFFFFFFFF
    return h

class HashRing:
    def __init__(self, vnodes=50):
        self.vnodes = vnodes
        self.points = []  # sorted list of (hash, node)

    def add_node(self, name):
        for i in range(self.vnodes):
            bisect.insort(self.points, (fnv1a(f'{name}#{i}'), name))

    def remove_node(self, name):
        self.points = [p for p in self.points if p[1] != name]

    def get_node(self, key):
        if not self.points:
            return None
        i = bisect.bisect_left(self.points, (fnv1a(str(key)),))
        return self.points[i % len(self.points)][1]

Follow-ups: replication (the next N distinct nodes clockwise), weighted nodes (more vnodes), hot keys (consistent hashing balances keys, not load), and rendezvous hashing as an alternative. Plain FNV clusters similar strings; production rings use a better mixer (murmur3, xxhash).

2. Check 1 back ↑

B. Modulo-N remaps almost every key when N changes; consistent hashing moves only about 1/N of keys

Modulo hashing couples every key to N, so a membership change reshuffles nearly everything. The ring assigns each key to the first node clockwise, so only neighbours of the change move.

3. Check 2 back ↑

A. Add many virtual nodes per physical node to even out load, and weight bigger machines with more of them

Virtual nodes spread each physical node around the ring, evening out load and letting heavier machines carry proportionally more keys.
