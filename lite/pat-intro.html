How to run a coding round

A repeatable routine for the first five minutes, and for the last five.

Most candidates do not fail on the algorithm. They fail on process under pressure. Use the same routine every time, so it becomes automatic:

  1. Restate the problem in your own words and confirm.
  2. Clarify input size, types, empty input, duplicates, negative numbers, ordering, memory limits.
  3. Examples: one normal, one edge case. Say the expected output.
  4. Brute force first (say it and its complexity), then name the bottleneck.
  5. Pick the pattern and state the invariant before you type.
  6. Code in small, named steps. Narrate decisions, not syntax.
  7. Test by hand on your examples, then on an edge case. Fix before the interviewer finds it.
  8. State complexity (time and space) and one follow-up improvement.
If you are stuck: say what you know, simplify (smaller input, one dimension, sorted input), solve that, then generalise. Silence is the real failure mode. Thinking aloud shows the process they are scoring.

Recognise the pattern from the wording

If the problem says…Think…
longest / shortest contiguous range, with a conditionsliding window, two pointers
overlaps, meetings, ranges, schedulessort by start, sweep, heap of end times
grid, connections, dependencies, “reachable”graph: BFS / DFS / union-find / topological sort
cheapest / fewest steps with weightsDijkstra (or BFS if unweighted)
k largest / smallest, merge sorted streamsheap
minimise the maximum / smallest value that worksbinary search on the answer
number of ways / min cost with overlapping subproblemsdynamic programming
prefix lookups, autocompletetrie

Practise in timed mode (the Timed button on every exercise): the target times are realistic interview budgets. Do not look at the hint or solution until time is up.

Answer key

1. Quick check back ↑

B. A variable-size sliding window, because all numbers are positive so the sum is monotonic

Positive numbers make the window sum monotonic: growing it increases the sum, shrinking it decreases it, so two pointers give O(n). With negative numbers that guarantee disappears.

2. Quick check back ↑

B. Say what you have so far (brute force and its cost, what you are trying to improve), so they can follow and nudge you

Interviewers score your reasoning. A narrated partial solution earns hints and credit. Silence gives them nothing to evaluate.

3. Check 1 back ↑

A. Stating the brute force and its complexity, which names the bottleneck the optimal solution must beat

Saying the brute force and its cost first frames the trade-off and earns credit even if the optimal stalls.

4. Check 2 back ↑

C. Binary search on the answer with a feasible(x) check

Minimise-the-maximum signals monotonic feasibility: if x works, larger x works, so binary-search x.
