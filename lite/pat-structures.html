Tries & union-find

Two data structures that turn awkward problems into short code.

Trie

A tree where each edge is a character. Lookup and prefix queries cost O(length of the word), regardless of how many words are stored. Use it for autocomplete, prefix counts and dictionary matching.

Union-find (disjoint set)

Maintains groups under “these two are connected” updates. find returns a group's representative, union merges two groups. With path compression it is effectively O(1) per operation. Use it for connected components, “are these accounts linked”, Kruskal's minimum spanning tree and cycle detection in undirected graphs.

Answer key

1. Autocomplete with a trie back ↑

Hint: Each node is a dict of children plus an is_word flag. To suggest: walk down the prefix (return [] if it breaks), then DFS the subtree visiting children in sorted order so results come out alphabetically, stopping once you have limit words.

Reference solution:

class Trie:
    def __init__(self):
        self.children = {}
        self.is_word = False

    def insert(self, word):
        node = self
        for ch in word:
            node = node.children.setdefault(ch, Trie())
        node.is_word = True

    def suggest(self, prefix, limit=3):
        node = self
        for ch in prefix:
            node = node.children.get(ch)
            if node is None:
                return []
        out = []

        def dfs(n, path):
            if len(out) >= limit:
                return
            if n.is_word:
                out.append(prefix + path)
            for ch in sorted(n.children):
                dfs(n.children[ch], path + ch)

        dfs(node, '')
        return out

Real autocomplete adds ranking (store a score per word and keep a top-k per node), sharding by prefix, and caching hot prefixes. Time per query is O(prefix + visited nodes), independent of how many words are stored.

2. Connected components (union-find) back ↑

Hint: Union-find: parent[] starts as identity; find(x) follows parents with path compression; union merges two roots and decrements the component counter only when the roots differ. Do not use recursion for find on a 100k chain.

Reference solution:

def count_components(n, edges):
    parent = list(range(n))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]  # path halving
            x = parent[x]
        return x

    count = n
    for u, v in edges:
        ru, rv = find(u), find(v)
        if ru != rv:
            parent[ru] = rv
            count -= 1
    return count

Union-find shines when edges arrive incrementally (online) and you only need connectivity. For "is there a path" on a static graph a BFS is just as good. Mention union by rank for the formal inverse-Ackermann bound.
