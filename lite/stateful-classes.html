Design-a-class problems

LRU cache and rate limiter: clean APIs, injectable clocks, invariants.

These problems test whether you can maintain invariants across operations. Senior moves: inject dependencies (a clock!) so the code is testable, define behavior at edges up front, and keep the public surface tiny.

In Python an OrderedDict (move_to_end, popitem(last=False)) gives you an LRU in a few lines. In interviews, also be ready to explain the classic hash map + doubly linked list version (O(1) get/put, which is what OrderedDict is underneath) and the thread-safety follow-ups.

Simulation: Token bucket rate limiter

Each request spends one token. Tokens refill continuously up to the capacity. Capacity is your burst tolerance, refill rate is your sustained throughput.

Try this in the full app:

  • Press Burst ×10 with capacity 5: the first 5 pass, the rest are rejected.
  • Wait a few seconds and burst again: the bucket has refilled.
  • Turn on auto traffic at 8/s with a refill of 2/s: roughly three quarters of requests are rejected in steady state.
  • Raise capacity but not the refill rate: bigger bursts, same long-run rate.

Answer key

1. LRU cache back ↑

Hint: collections.OrderedDict has move_to_end(key) and popitem(last=False). Careful with “if not self.d.get(key)”: it treats 0 as a miss. Use “in”.

Reference solution:

from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.data = OrderedDict()

    def get(self, key):
        if key not in self.data:
            return None
        self.data.move_to_end(key)
        return self.data[key]

    def put(self, key, value):
        if key in self.data:
            self.data.move_to_end(key)
        self.data[key] = value
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)

Be ready to explain the classic hash map + doubly linked list version too (OrderedDict is exactly that under the hood), and what changes for thread-safety.

2. Token-bucket rate limiter back ↑

Hint: Do not use a timer. Refill lazily on every call: tokens = min(capacity, tokens + elapsed * rate).

Reference solution:

import time

class RateLimiter:
    def __init__(self, capacity, refill_per_sec, now=time.monotonic):
        self.capacity = capacity
        self.rate = refill_per_sec
        self.now = now
        self.tokens = float(capacity)
        self.last = now()

    def _refill(self):
        t = self.now()
        self.tokens = min(self.capacity, self.tokens + (t - self.last) * self.rate)
        self.last = t

    def try_acquire(self, n=1):
        self._refill()
        if self.tokens >= n:
            self.tokens -= n
            return True
        return False

Follow-ups to be ready for: distributed limiting (Redis + a Lua script for atomicity), sliding window vs token bucket, fairness per tenant, returning Retry-After. Use time.monotonic, never time.time, for intervals.

3. Check 1 back ↑

A. Inject the clock (default time.time) so tests can pass a fake clock and advance time deterministically

Injecting dependencies like a clock keeps the public surface tiny and the invariant testable; define edge behavior up front instead of sleeping in tests.

4. Check 2 back ↑

C. A get must mark the key most-recently-used (move_to_end) so eviction drops the truly least-used entry

The LRU invariant is maintained across operations: every get and put refreshes recency, and eviction removes the least-recently-used entry in O(1).
